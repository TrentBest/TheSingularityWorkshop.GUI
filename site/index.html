The boundary

One semantic model. Separate platform adapters.

The GUI model describes what the interface means. Each adapter owns the platform-specific work of presenting it. The consuming experience retains its own state, behavior, and domain meaning.

What is actually in this repository?

Five packages divide the work by responsibility. The first is the neutral contract; the others are adapters with distinct targets. They are not five competing GUI frameworks.

The next boundary

Host a living scene without absorbing its engine.

GUI now has a Blazor host seam for semantic Viewport nodes. The host supplies the actual presentation fragment; Renderer and Visualize remain responsible for observer policy and visual execution.

Live integration preview: this is the actual Visualize Soldier Field WebGPU runner, copied into the GUI Pages artifact at a recorded Visualize development revision. Renderer policy and FSM state are generated by the .NET pipeline; the browser consumes that manifest and executes graphics on the visitor's GPU when supported.

Renderer · Visualize · GUI.Blazor

Host-owned visualization viewport

A GUI page can declare where a visual experience belongs. A host can place a Visualize scene, WebGPU runner, or another renderer inside that region without making GUI own scene state, GPU resources, or domain execution.

Implemented slice: nested Viewport delegation, stable GUI identity, accessible region metadata, and explicit host-fragment requirements are covered by Blazor tests.
Not yet claimed: automatic Renderer policy negotiation, spatial input routing, resize/disposal lifecycle, GPU availability, or full spatial adapter parity.
